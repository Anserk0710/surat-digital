# Admin platform dan perusahaan

Admin platform adalah karyawan aktif yang sudah terhubung ke akun Supabase Auth. Hak `is_platform_admin` hanya dapat diberikan atau dicabut melalui operasi tepercaya dengan `DIRECT_URL`; API pengguna tidak dapat mengubahnya.

Setelah migrasi `20261119010000_organization_management` dan `20261119102200_organization_change_privileges` diterapkan, operator menetapkan variabel `PLATFORM_ADMIN_EMPLOYEE_ID`, `PLATFORM_ADMIN_AUTH_USER_ID`, `PLATFORM_ADMIN_EXPECTED_DATABASE_HOST`, `PLATFORM_ADMIN_EXPECTED_DATABASE_NAME`, `PLATFORM_ADMIN_ACTION=grant`, dan `PLATFORM_ADMIN_ACK=YES`, lalu menjalankan `npm run platform-admin:set -w @surat-digital/api`. Gunakan `PLATFORM_ADMIN_ACTION=revoke` untuk mencabut hak. Script menolak host/database yang tidak cocok dan akun yang belum aktif atau tidak cocok dengan ID Supabase Auth yang diharapkan.

Halaman Organisasi menampilkan semua perusahaan hanya bagi admin platform. Saat membuat perusahaan, admin platform memasukkan kode, nama perusahaan, email, dan nama admin pertama. Sistem mengirim undangan Supabase, lalu membuat perusahaan, akun admin, grup `COMPANY_ADMIN`, dan izin `System.Configure`, `User.View`, `User.Manage`, `Group.View`, serta `Group.Manage` dalam satu transaksi database. Login admin baru menggunakan alamat email. Admin perusahaan hanya melihat dan mengubah perusahaan sendiri.

Admin platform memilih perusahaan di halaman Organisasi sebelum membuka Kantor, Divisi, Jabatan, Relasi Kantor–Divisi, dan Penempatan. Semua request untuk master tersebut membawa `companyId` terpilih. Backend hanya menerima cakupan perusahaan lain dari admin platform; admin perusahaan tetap terbatas pada perusahaan sendiri.

Admin platform dapat mengubah, menonaktifkan, mengaktifkan kembali, atau menghapus permanen perusahaan lain. Kedua tindakan penghapusan memerlukan checkbox konfirmasi di tampilan. API memakai `DELETE /organization/companies/:id?force=true` untuk menonaktifkan perusahaan beraktivitas dan `?permanent=true&force=true` untuk hapus permanen. Nonaktif menyimpan data dan membuat akses pengguna perusahaan tidak berlaku. Hapus permanen membersihkan dokumen, karyawan, penempatan, grup, sesi, master, dan riwayat perusahaan, lalu menghapus akun Supabase terkait. Bila penghapusan akun Supabase gagal, perusahaan tetap nonaktif dan operasi hapus permanen dapat diulang. Riwayat audit akhir tindakan hapus tetap dicatat di platform.

Hapus permanen master turunan juga memerlukan checkbox. Penghapusan Kantor atau Divisi membersihkan dokumen penerbit, penempatan, dan relasi Kantor–Divisi terkait; penghapusan Relasi Kantor–Divisi membersihkan dokumen dan penempatan terkait; penghapusan Jabatan membersihkan penempatan terkait. Penonaktifan master mempertahankan data turunannya. Perubahan master dicatat secara atomik bersama mutasi di `organization_changes`.
